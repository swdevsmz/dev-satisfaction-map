# スコア算出とデータの透明性

このページは、企業の幸福度スコアを再現できるように、入力値、正規化、欠損値、データの出典と鮮度を説明します。

## 算出手順

1. 各データソースから企業の指標を取得します。
2. 指標を0〜100に正規化します。
3. 下表の重みで加重平均し、0〜100に収めて小数第1位に丸めます。

| 指標 | 入力範囲 | 正規化 | 重み |
|---|---:|---|---:|
| 技術スタックの新しさ | 1〜10 | `((x - 1) / 9) * 100` | 0.20 |
| リモート率 | 0〜100% | `x` | 0.20 |
| 月間残業時間 | 0以上 | `max(0, ((80 - x) / 80) * 100)` | 0.20 |
| 離職率 | 0〜100% | `max(0, 100 - x)` | 0.10 |
| 定着率 | 0〜100% | `x` | 0.10 |
| 開発環境 | 1〜10 | `((x - 1) / 9) * 100` | 0.10 |
| スキルアップ支援 | 1〜10 | `((x - 1) / 9) * 100` | 0.10 |

実装の正本は [`src/utils/scoring.ts`](../src/utils/scoring.ts)、テストは [`src/utils/scoring.test.ts`](../src/utils/scoring.test.ts) です。

## データソースと限界

- **GitHub**: 公開リポジトリ、使用言語、スター、最近のイベントから技術スタックと開発環境を推定します。観測できたOSS活動だけを表します。
- **connpass**: 勉強会の開催頻度・定員・技術タグからスキルアップ支援を推定します。掲載されない社内制度は観測できません。
- **OpenWork**: 口コミページから残業・定着などの値を取得します。口コミの母集団と掲載時期に偏りがあります。
- **IR**: 企業が公式に開示した資料への到達性と記載値を使います。企業ごとに開示範囲が異なります。

出典URLと取得日時は `raw_documents` に保存されます。外部ページの値は公式統計との一致を保証しません。

## 鮮度と信頼度

信頼度は出典の数と取得時点を表す補助指標で、幸福度スコアそのものを変更しません。実測値を含むOpenWork/IRは重み2、推定値中心のGitHub/connpassは重み1です。鮮度係数は30日以内=1.0、90日以内=0.7、180日以内=0.4、それより古い=0.1です。各ソースの最新取得値だけを採用し、最大合計6を100として正規化します。

実装とテストは [`src/utils/reliability.ts`](../src/utils/reliability.ts) と [`src/utils/reliability.test.ts`](../src/utils/reliability.test.ts) にあります。

## 欠損値の扱い

取得できない指標は抽出層では `null` として保持します。画面へ変換する際は比較可能な初期値を補い、取得元フラグと信頼度を別に表示します。補完値は実測値ではありません。未取得のソースは信頼度に加算されず、データソースバッジでも未取得として扱います。

## パーソナルスコア

ユーザーが重要度を設定した場合、その重みだけで再正規化します。全て0の場合は標準スコアに戻ります。
