# エンジニア幸福度スコアリング仕様書

## 1. 概要

エンジニア幸福度マップでは、企業のエンジニアにとっての働きやすさを **幸福度スコア** として数値化し、ユーザーが企業を比較・評価できるようにしています。

### 1.1 目的
- 企業のエンジニアにとっての魅力度を 0–100 の一次元スコアで表現
- 複数の指標をバランスよく考慮し、偏った評価を避ける
- ユーザーが重視する項目に応じたパーソナルスコア計算に対応

### 1.2 対象
- 日本の IT 企業（約 73 社）
- 各企業のエンジニア向けの働き方・環境情報

## 2. スコアリングの基本構成

### 2.1 7つの基本評価指標

| # | 指標 | 内容 | 単位 | 範囲 | 反転 | 重み |
|---|------|------|------|------|------|------|
| 1 | 技術スタック現代性 | 使用技術の最新度・先進性 | スコア | 1–10 | ❌ | 20% |
| 2 | リモート対応率 | リモートワーク可能な割合 | パーセント | 0–100% | ❌ | 20% |
| 3 | 残業時間（少ないほど良い） | 月間推定残業時間 | 時間 | 0–80+ | ✅ | 20% |
| 4 | 離職率（低いほど良い） | エンジニアの離職率 | パーセント | 0–100% | ✅ | 10% |
| 5 | 定着率 | エンジニアの定着率 | パーセント | 0–100% | ❌ | 10% |
| 6 | 開発環境スコア | 開発・勤務環境の充実度 | スコア | 1–10 | ❌ | 10% |
| 7 | スキルアップ支援度 | 研修・勉強会支援の手厚さ | スコア | 1–10 | ❌ | 10% |

**重み合計**: 100% (1.00)

### 2.1.1 加点項目：技術発信度（ボーナス）

上記 7 つの基本指標に加え、以下の項目で加点します。

| 項目 | 内容 | 上限加点 |
|------|------|----------|
| **GitHub 活動度** | 公開リポジトリの活発度（スター数、更新頻度） | +5点 |
| **Connpass イベント開催** | 勉強会主催実績（技術コミュニティへの貢献） | +5点 |

加点上限: 基本スコアが最大 100 点になるようキャップ

### 2.2 各指標の定義

#### 2.2.1 技術スタック現代性（重み: 20%）
- **定義**: 企業で使用されている主要技術の最新度・先進性
- **データソース**: **求人情報**（実測値）
  - Wantedly、Indeed、LAPRAS、その他求人サイトの採用募集要項
  - 「使用技術」「開発言語」等の記載から抽出
- **測定方法**: 
  - 募集要項に記載されている主要開発言語・フレームワークから採点
  - 複数の技術スタックがある場合は平均値を使用
  - スコア算出基準:
    - **Go, Rust, TypeScript, Kotlin, Swift 等の最新言語採用** → 9–10 点
    - **Python, Java, Ruby, C# 等の成熟言語** → 6–8 点
    - **PHP, C, C++ 等のレガシー言語中心** → 1–5 点
- **スコア範囲**: 1–10
- **根拠**: エンジニアのスキル獲得機会、キャリア価値に直結
- **信頼度**: 🟢 高（実測値、求人情報に基づく）

#### 2.2.2 リモート対応率（重み: 20%）
- **定義**: リモートワークが可能なエンジニアの割合
- **データソース**: **OpenWork**（実測値）
  - OpenWork は求人情報・社員レビューから実データを集計
  - 匿名社員による勤務形態の報告値
- **測定方法**:
  - 100% フルリモート → 100 点
  - 一部リモート (ex. 月 2 日出社) → 70–90 点
  - ハイブリッド (週 2–3 日出社) → 40–60 点
  - 出社必須 → 0–20 点
- **スコア範囲**: 0–100%
- **根拠**: ワークライフバランス、居住地の自由度に影響
- **信頼度**: 🟢 高（実測値）

#### 2.2.3 残業時間（重み: 20%）
- **定義**: 月間の平均推定残業時間
- **データソース**: **OpenWork**（実測値）
  - OpenWork は社員レビューから月間残業時間を集計
  - 実際の残業報告に基づく平均値
- **測定方法**:
  - 10 時間以下 → 優良（スコア 80 以上）
  - 20 時間程度 → 標準（スコア 60–70）
  - 30 時間程度 → やや多い（スコア 40–50）
  - 45 時間以上 → 多い（スコア 20 以下）
- **スコア範囲**: 0–80+ 時間
- **正規化基準**: 80 時間を基準に反転（以下参照）
- **根拠**: 身体的・精神的健康、ワークライフバランスの最重要指標
- **信頼度**: 🟢 高（実測値、社員報告）

#### 2.2.4 離職率（重み: 10%）
- **定義**: エンジニアの年間離職率
- **データソース**: **OpenWork**（実測値）
  - OpenWork は企業の有価証券報告書・社員レビューから離職率を推定
  - 公開企業の場合は有報値を優先使用
- **測定方法**:
  - 5% 以下 → 優秀（定着力高い）
  - 10–15% → 標準
  - 20% 以上 → やや高い
  - 30% 以上 → 離職が多い
- **スコア範囲**: 0–100%
- **根拠**: 企業の働き方・カルチャーの健全性を反映
- **信頼度**: 🟢 高（実測値、有報データ利用）

#### 2.2.5 定着率（重み: 10%）
- **定義**: エンジニアの定着率（1 - 離職率）
- **データソース**: **OpenWork**（実測値）
  - OpenWork から離職率を取得し、自動計算
  - 定着率 = 100% - 離職率
- **測定方法**:
  - 95% 以上 → 優秀
  - 85–95% → 良好
  - 75–85% → 標準
  - 70% 以下 → やや低い
- **スコア範囲**: 0–100%
- **根拠**: 企業への信頼度・満足度の指標
- **信頼度**: 🟢 高（実測値、離職率から自動計算）

#### 2.2.6 開発環境スコア（重み: 10%）
- **定義**: 開発・勤務環境の充実度（リモート環境、ツール、勤務形態等）
- **データソース**: **求人情報**（実測値）
  - Wantedly、Indeed、LAPRAS、その他求人サイトの採用募集要項
  - 「勤務形態」「福利厚生」「社員インタビュー」等から抽出
- **測定方法**:
  - 募集要項に記載されている環境・支援制度から採点
  - スコア算出基準:
    - **フルリモート対応、最新開発ツール、柔軟勤務制** → 9–10 点
    - **ハイブリッド勤務、モダンツール導入、学習環境整備** → 7–8 点
    - **一部モダン化、基本的環境整備** → 5–6 点
    - **オフィス勤務必須、レガシー環境** → 1–4 点
  - 加点項目:
    - リモート可能: +2 点
    - フレックス制度: +1 点
    - MacBook/高性能PC支給: +1 点
    - 開発環境自由化: +1 点
    - その他最新ツール導入: +1 点
- **スコア範囲**: 1–10
- **根拠**: 生産性、ワークライフバランス、DX 成熟度に影響
- **信頼度**: 🟢 高（実測値、求人情報に基づく）

#### 2.2.7 スキルアップ支援度（重み: 10%）
- **定義**: 教育・研修・勉強会支援の手厚さ
- **データソース**: **求人情報**（実測値）
  - Wantedly、Indeed、LAPRAS、その他求人サイトの採用募集要項
  - 「スキルアップ支援」「研修制度」「社員インタビュー」等から抽出
- **測定方法**:
  - 募集要項に記載されている教育支援制度から採点
  - スコア算出基準:
    - **充実した研修制度、学習時間確保、外部研修支援、資格取得支援等が複数** → 9–10 点
    - **研修制度あり、勉強会開催、一部外部研修支援** → 7–8 点
    - **基本的な研修制度、学習環境あり** → 5–6 点
    - **支援がほぼなし、自己学習が基本** → 1–4 点
  - 加点項目:
    - 社内研修制度: +2 点
    - 外部研修支援: +1 点
    - 資格取得支援（費用補助）: +1 点
    - 社内勉強会開催: +1 点
    - 学習時間確保制度: +1 点
- **スコア範囲**: 1–10
- **根拠**: キャリア開発機会、自己成長の機会に影響
- **信頼度**: 🟢 高（実測値、求人情報に基づく）

## 3. 配点方法と正規化

### 3.1 正規化フォーム

各指標を 0–100 スケールに正規化します。

#### 3.1.1 技術スタック現代性（1–10 → 0–100）
```
正規化スコア = ((元スコア - 1) / 9) × 100
```

**例**:
- スコア 1 → (1-1)/9 × 100 = 0 点
- スコア 5 → (5-1)/9 × 100 = 44.4 点
- スコア 10 → (10-1)/9 × 100 = 100 点

#### 3.1.2 リモート対応率（0–100% → 0–100）
```
正規化スコア = 元スコア（そのまま）
```

**例**:
- 0% → 0 点
- 50% → 50 点
- 100% → 100 点

#### 3.1.3 残業時間（0–80+ → 0–100、反転）
```
正規化スコア = max(0, ((80 - 元スコア) / 80) × 100)
```

**解説**: 80 時間を基準に反転。残業が少ないほど高スコア。

**例**:
- 10 時間 → ((80-10)/80) × 100 = 87.5 点
- 30 時間 → ((80-30)/80) × 100 = 62.5 点
- 80 時間 → ((80-80)/80) × 100 = 0 点
- 100 時間 → max(0, ((80-100)/80)×100) = 0 点 （下限）

#### 3.1.4 離職率（0–100% → 0–100、反転）
```
正規化スコア = 100 - 元スコア
```

**例**:
- 5% 離職 → 100 - 5 = 95 点
- 15% 離職 → 100 - 15 = 85 点
- 30% 離職 → 100 - 30 = 70 点

#### 3.1.5 定着率（0–100% → 0–100）
```
正規化スコア = 元スコア（そのまま）
```

**例**:
- 80% 定着 → 80 点
- 95% 定着 → 95 点

#### 3.1.6 開発環境スコア（1–10 → 0–100）
```
正規化スコア = ((元スコア - 1) / 9) × 100
```

**例**:
- スコア 1 → 0 点
- スコア 5 → 44.4 点
- スコア 10 → 100 点

#### 3.1.7 スキルアップ支援度（1–10 → 0–100）
```
正規化スコア = ((元スコア - 1) / 9) × 100
```

**例**:
- スコア 1 → 0 点
- スコア 5 → 44.4 点
- スコア 10 → 100 点

## 4. 幸福度スコア（総合スコア）の計算

### 4.1 計算式

```
幸福度スコア = Σ (正規化スコア × 重み)
            = 技術 × 0.20 
            + リモート × 0.20 
            + 残業 × 0.20 
            + 離職 × 0.10 
            + 定着 × 0.10 
            + 開発環境 × 0.10 
            + スキルアップ × 0.10

最終スコア = round(min(100, max(0, 幸福度スコア)) × 10) / 10
```

### 4.2 計算例

**企業 A の例**（フルリモート、技術最新、残業少ない）:
```
技術スタック:       8  → 正規化 77.8 × 0.20 = 15.56
リモート率:         95 → 正規化 95   × 0.20 = 19.00
残業時間:          15 → 正規化 81.3 × 0.20 = 16.25
離職率:            10 → 正規化 90   × 0.10 = 9.00
定着率:            90 → 正規化 90   × 0.10 = 9.00
開発環境:           8 → 正規化 77.8 × 0.10 = 7.78
スキルアップ:       7 → 正規化 66.7 × 0.10 = 6.67
                                    ─────────
                                    83.26 → 83.3 点
```

**企業 B の例**（レガシー、出社必須、残業多い）:
```
技術スタック:       3  → 正規化 22.2 × 0.20 = 4.44
リモート率:         20 → 正規化 20   × 0.20 = 4.00
残業時間:          50 → 正規化 37.5 × 0.20 = 7.50
離職率:            25 → 正規化 75   × 0.10 = 7.50
定着率:            75 → 正規化 75   × 0.10 = 7.50
開発環境:           3 → 正規化 22.2 × 0.10 = 2.22
スキルアップ:       2 → 正規化 11.1 × 0.10 = 1.11
                                    ─────────
                                    34.27 → 34.3 点
```

## 5. データ信頼度インジケータ

### 5.1 概要

各企業のスコアがどの程度信頼できるかを、**データ信頼度スコア** として 0–100 で表示します。

ユーザーに以下を明示：
- どのデータソースが取得済みか
- データの新鮮度（最終更新日時）
- 信頼度レベル（高/中/低）

### 5.2 データソース別の特性

| ソース | 種別 | 信頼度 | 説明 | 対象指標 |
|--------|------|--------|------|----------|
| **OpenWork** | 実測値 | 🟢 高 | 社員実報告・有報データ。最も信頼性高い | リモート率、残業時間、離職率、定着率 |
| **求人情報** | 実測値 | 🟢 高 | 企業が公開している募集要項。採用募集時点での最新情報 | 技術スタック、開発環境、スキルアップ支援 |
| **GitHub** | 推定値 | 🟡 中 | リポジトリ分析。加点項目用（技術発信度） | GitHub活動度（加点項目） |
| **Connpass** | 推定値 | 🟡 中 | イベント開催実績。加点項目用（技術コミュニティ貢献） | Connpassイベント開催（加点項目） |

### 5.3 信頼度スコアの計算

```
信頼度スコア = (Σ (ソースの重み × 鮮度係数)) / 最大値 × 100

ソースの重み:
  - OpenWork: 2 点
  - 求人情報: 2 点
  - GitHub: 1 点（加点項目用）
  - Connpass: 1 点（加点項目用）
  最大値: 4 点

鮮度係数（データ取得日からの経過日数）:
  - 0–30日以内: 1.0
  - 31–90日: 0.7
  - 91–180日: 0.4
  - 180日以上: 0.1
```

**例**:
```
OpenWork (30日以内) + 求人情報 (60日前)
= (2 × 1.0 + 2 × 0.7) / 4 × 100
= 3.4 / 4 × 100
= 85% → 信頼度「高」
```

### 5.4 信頼度レベルの判定

| スコア範囲 | レベル | 説明 |
|----------|--------|------|
| 70–100% | 🟢 高 | OpenWork が最新。信頼性高い |
| 40–69% | 🟡 中 | 複数ソース取得済み、または一部古い |
| 0–39% | 🔴 低 | データが不足・古い。参考値 |

### 5.5 UI 表示方法

**詳細ページでの表示**:
```
データ信頼度: [高] 87%
更新: 5日前

取得ソース:
  [✓ OpenWork (実測値)] [✓ GitHub (推定値)] [ Connpass (推定値)]
```

**ツールチップ**（ホバーで表示）:
```
OpenWork: 社員報告による実データ。最新。
GitHub: リポジトリ分析から推定。60日前。
Connpass: イベント開催実績から推定。未取得。
```

### 5.6 ユーザーへのガイダンス

詳細ページに以下を記載：

```
💡 スコアの見方

この幸福度スコアは複数のデータソースから算出されています。

✅ 信頼度が高い指標:
  - リモート率、残業時間、離職率、定着率 (OpenWork 実データ)

⚠️ 信頼度が中程度の指標:
  - 技術スタック、開発環境 (GitHub リポジトリ分析)

💭 参考程度の指標:
  - スキルアップ支援度 (Connpass イベント開催実績)

※ データが不足している企業は、実データ取得までの間、
   ニュートラルな値で仮算出しています。
```

## 6. スコア判定と色分け

### 5.1 判定基準

| スコア範囲 | 判定 | カラー | 意味 |
|----------|------|--------|------|
| 70–100 | 優秀 | 🟢 緑 | エンジニアに最適な環境 |
| 40–69 | 標準 | 🟡 黄 | 平均的な環境 |
| 0–39 | 要改善 | 🔴 赤 | 改善が必要な環境 |

### 5.2 判定ロジック

```typescript
function getScoreColor(score: number): 'green' | 'yellow' | 'red' {
  if (score >= 70) return 'green'
  if (score >= 40) return 'yellow'
  return 'red'
}
```

## 6. デフォルト値（データ未取得時）

求人情報ソースへの変更により、**ほぼすべての企業で求人情報は取得可能** となるため、デフォルト値の依存度は低下します。

ただし、OpenWork データ（リモート率、残業時間、離職率、定着率）未取得時のデフォルト値は以下の通り：

| 指標 | デフォルト値 | 正規化後 | 根拠 |
|------|------------|---------|------|
| リモート率 | 50% | 50 | ニュートラル（リモート未対応・対応済みの中間） |
| 残業時間 | 30 時間 | 62.5 | 標準的な月間残業時間 |
| 離職率 | 15% | 85 | 業界平均前後 |
| 定着率 | 85% | 85 | 離職率 15% に対応 |

**求人情報から取得される指標** （ほぼすべての企業で取得可能）:
- 技術スタック（デフォルト不要）
- 開発環境（デフォルト不要）
- スキルアップ支援（デフォルト不要）

### 6.1 データ未取得時の対応

1. **求人情報が取得できない場合** → 「データ待機中」と表示し、スコアを算出しない
2. **OpenWork データのみ未取得** → 求人情報ベースで一部スコアを表示
3. **定期的にデータ更新** → 月 1 回程度で求人情報・OpenWork データを再取得

## 7. パーソナルスコア機能

### 7.1 機能概要

ユーザーが「重視する項目」をスライダーで調整し、自分にとっての最適スコアを計算できます。

### 7.2 ユーザーウェイト

各指標について、ユーザーが 0–3 の重要度を選択：
- 0: 気にしない
- 1: やや重視
- 2: 重視
- 3: 最重視

### 7.3 計算方法

```
ユーザーウェイト合計 = Σ(ユーザーの重要度設定)

パーソナルスコア 
  = Σ(正規化スコア × (ユーザーウェイト / 合計))

フォールバック: ウェイト合計が 0 の場合は、幸福度スコアを返す
```

**例**: リモート率とスキルアップ重視ユーザー
```
ユーザーウェイト:
  リモート: 3
  スキルアップ: 3
  その他: 0
合計: 6

パーソナルスコア 
  = (リモート正規化 × 3/6) 
  + (スキルアップ正規化 × 3/6)
```

## 8. 求人情報の取得方法

### 8.1 対象とする求人情報

以下の複数の求人プラットフォームから企業の採用募集要項を定期的に取得：

| プラットフォーム | 主な用途 | API/スクレイピング |
|----------------|---------|------------------|
| **Wantedly** | スタートアップ・ベンチャー採用情報 | API 利用可 |
| **Indeed** | 広く網羅的な求人情報 | スクレイピング |
| **LAPRAS** | エンジニア向け求人・スカウト | API 利用可 |
| **LinkedIn** | グローバル企業の採用情報 | スクレイピング |
| **自社採用サイト** | 企業の最新採用情報 | スクレイピング |

### 8.2 取得方法

**定期スクレイピング**（月 1 回程度）:
1. 各プラットフォームから企業の最新募集要項を取得
2. 「使用技術」「勤務形態」「支援制度」等のキーワードを抽出
3. 言語処理 (NLP) により自動採点
4. `company_scrapes` テーブルに source = `job_posting` として保存

### 8.3 自動採点ロジック（NLP）

**技術スタック抽出例**:
```
募集要項テキスト:
「Go、TypeScript、React、Docker、Kubernetes を使用した
 マイクロサービス開発に携わります」

抽出結果:
  - Go (最新言語) ✓
  - TypeScript (最新言語) ✓
  - React (最新フレームワーク) ✓
  - Docker (モダン開発環境) ✓
  - Kubernetes (最新インフラ) ✓

スコア: 9–10 点
```

**開発環境スコア抽出例**:
```
募集要項テキスト:
「フルリモート対応、MacBook Pro 支給、
 フレックスタイム制度、自由な開発環境」

加点:
  - フルリモート: +2 点
  - MacBook支給: +1 点
  - フレックス: +1 点
  - 開発環境自由化: +1 点
  基本点: 2 点

スコア: 2 + 2 + 1 + 1 + 1 = 7 点
```

### 8.4 データ品質保証

- **手動レビュー**: サンプリング検証（月 10 企業程度）
- **異常値検知**: 急激な変化は手動確認
- **更新頻度**: 募集要項が公開されている限り、月 1 回は更新
