# エンジニア幸福度スコアリングシステム - 要件定義

## 1. 機能要件

### 1.1 幸福度スコア計算 (REQ-1)

7つの基本評価指標を0–100に正規化し、重み付き平均で総合スコア（0–100）を算出する。

**指標と重み**:
| 指標 | 重み | 正規化方式 | 反転 |
|------|------|----------|------|
| 技術スタック現代性 | 20% | (スコア1-10) → 0-100 | ❌ |
| リモート対応率 | 20% | (パーセント) → そのまま | ❌ |
| 残業時間 | 20% | (時間) → 80h基準で反転 | ✅ |
| 離職率 | 10% | (パーセント) → 反転 | ✅ |
| 定着率 | 10% | (パーセント) → そのまま | ❌ |
| 開発環境スコア | 10% | (スコア1-10) → 0-100 | ❌ |
| スキルアップ支援度 | 10% | (スコア1-10) → 0-100 | ❌ |

**計算式**:
```
幸福度スコア = Σ (正規化スコア × 重み)
最終スコア = round(min(100, max(0, スコア)) × 10) / 10
```

### 1.2 ボーナスポイント (REQ-2)

基本スコアに加えて以下の項目で加点（合計最大10点）:
- GitHub活動度: +5点
- Connpassイベント開催: +5点
- 最終スコアは100点にキャップ

### 1.3 パーソナルスコア計算 (REQ-3)

ユーザーが各指標の重要度（0-3）を調整し、カスタムスコアを計算:
- 0: 気にしない
- 1: やや重視
- 2: 重視
- 3: 最重視

**計算式**:
```
ウェイト合計 = Σ(ユーザーの重要度設定)
パーソナルスコア = Σ(正規化スコア × (ユーザーウェイト / 合計))
フォールバック: 合計0の場合は標準スコアを返す
```

### 1.4 スコア色分け (REQ-4)

スコア範囲に基づいた色分け表示:
- 70–100: 🟢 緑（優秀）
- 40–69: 🟡 黄（標準）
- 0–39: 🔴 赤（要改善）

### 1.5 データ信頼度インジケータ (REQ-5)

各企業のスコアの信頼性を0–100で表示:
- **ソース別の重み**: OpenWork(2点), 求人情報(2点), GitHub(1点), Connpass(1点)
- **鮮度係数**: 30日以内(1.0), 31-90日(0.7), 91-180日(0.4), 180日以上(0.1)
- **信頼度レベル**:
  - 70–100%: 🟢 高
  - 40–69%: 🟡 中
  - 0–39%: 🔴 低

### 1.6 デフォルト値 (REQ-6)

OpenWorkデータ未取得時のデフォルト値:
| 指標 | デフォルト | 正規化後 |
|------|----------|---------|
| リモート率 | 50% | 50 |
| 残業時間 | 30時間 | 62.5 |
| 離職率 | 15% | 85 |
| 定着率 | 85% | 85 |

## 2. 非機能要件

### 2.1 パフォーマンス (REQ-7)

- スコア計算: 1社あたり < 100ms
- バッチ計算: 73社全体 < 5秒

### 2.2 精度 (REQ-8)

- 正規化: 小数点第1位まで正確
- 合計重み: 1.00（誤差±0.01）

### 2.3 拡張性 (REQ-9)

- 新規指標の追加に対応可能
- 重み配分の動的変更に対応
- データソースの追加に対応

### 2.4 データ管理 (REQ-10)

- 月1回の定期更新対応
- 複数ソースからのデータ統合
- データの更新日時・鮮度管理

## 3. ユーザーニーズ

### 3.1 企業評価ユーザー (REQ-11)

複数企業を比較し、エンジニアにとっての最適企業を見つけたいユーザー:
- 総合スコアの表示
- 企業間の比較
- 色分けによる直感的な判定

### 3.2 自分重視型ユーザー (REQ-12)

自分にとって重要な項目に特化したスコアを見たいユーザー:
- パーソナルスコア機能
- スライダーで重要度調整

### 3.3 詳細分析ユーザー (REQ-13)

スコアの背景にあるデータを信頼したいユーザー:
- 指標の詳細説明
- データソース・信頼度表示
- データの新鮮度表示

## 4. 対象範囲

- **対象企業**: 日本のIT企業約73社
- **対象エンジニア**: 各企業のエンジニア向け情報
