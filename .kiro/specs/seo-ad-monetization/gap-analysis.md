# ギャップ分析レポート: seo-ad-monetization

## 分析サマリー

- **スコープ:** 9要件・計37受け入れ基準に対し、既存実装との差分を調査
- **活用可能な既存資産:** `react-helmet-async`（title/description設定済み）、AdSenseスクリプト（`index.html` に `async` 実装済み）、`viewport` meta、Tailwindレスポンシブレイアウト、Supabaseデータ層
- **完全未実装:** `robots.txt` / `sitemap.xml`・JSON-LD・canonical・完全OGP/Twitterカード・GA4・SNSシェアボタン・パンくずリスト・関連企業リンク・ローディングスケルトン・ルートベースのlazy loading
- **最大のアーキテクチャ判断:** CSR SPAにおけるOGP動的生成方式（SNSクローラー対応）を設計フェーズで決定が必要
- **推奨アプローチ:** ハイブリッド戦略（Option C）— 既存Helmet拡張＋新規コンポーネント群の組み合わせ

### 1.2 統合サーフェス

- `Company.id`（例: `"mercari-jp"`）がURLスラッグとして使用可能 → canonical・OGP URL生成に利用できる

## 5. 設計フェーズへの引き継ぎ事項（要決定）

1. **OGP動的生成の方式（最優先）:** CSR SPAではSNSクローラーがmetaタグを読み取れない。「全ページ共通の静的OGP画像1枚を使用する」「Vite SSG（vite-plugin-ssg）を導入する」「Supabase Edge FunctionsでOG画像を動的生成する」のいずれかを選択する必要がある。

2. **sitemap.xml の生成方式:** Supabaseから企業IDを取得してビルド時に静的生成するスクリプトか、Viteプラグインの採用を検討。企業が動的に追加される場合の更新戦略も必要。

3. **`Company` 型への `website` フィールド追加の要否:** Organization スキーマの `url` プロパティのためにDBスキーマ変更が必要か、代替として会社名でGoogle検索するURLを使用するかを設計フェーズで決定。

4. **フィルタリングページのルート設計:** 要件7-5「指標フィルタリングページへの内部リンク」は新規ルートの追加を意味する。スコープを確定する必要がある。

5. **プライバシーポリシーのコンテンツ:** GA4・AdSenseの利用に伴い、個人情報保護法・GDPRに準拠した記載が必要。
